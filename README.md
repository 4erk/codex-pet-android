# Codex Pet for Android

Нативное Android-приложение с прозрачным питомцем поверх ChatGPT/Codex. Состояние задач берётся из публичных Android-уведомлений ChatGPT; root, Accessibility, Shizuku, hooking и приватные файлы ChatGPT не используются.

> Кандидат на первый production-релиз: **0.6.0**. Production package: `com.mr4erk.codexpet`.

## Что умеет

- Android 11–16 (`minSdk 30`, `targetSdk 36`).
- Прозрачный `TYPE_APPLICATION_OVERLAY` без системного белого круга ChatGPT.
- Встроенный Violet Vixen v2: 9 состояний и 16 направлений взгляда.
- Импорт PNG/WebP/spritesheet/ZIP с ограничениями размера и защитой ZIP.
- Получение текущих задач из уведомлений ChatGPT.
- Автоматическое восстановление подключения к уведомлениям после сбоев/OEM kill.
- До 5 отдельных кликабельных реплик одновременно.
- Живые предпросмотры размера питомца, масштаба реплик и скорости анимации.
- Ручное и автоматическое обновление приложения через GitHub Releases.

## Реплики

Баблы привязаны к питомцу и двигаются вместе с ним без remove/add окон во время drag/snap.

В `0.6.0`:

- одиночный боковой бабл центрируется относительно питомца;
- короткая однострочная реплика имеет отдельную проверенную геометрию хвоста;
- 1–5 баблов размещаются в безопасной области экрана;
- если все не помещаются, лишние переходят на следующую страницу;
- внимание пользователя, ошибки и потеря связи не исчезают по таймеру;
- завершения и обычные сообщения показываются кратко.

Встроенный **Стенд** позволяет проверить 1–5 реплик и перетаскивать питомца без ожидания реальных уведомлений.

## Анимации

Основные состояния:

- покой;
- работа;
- проверка;
- ожидание ответа / восстановления связи;
- проблема;
- короткая реакция на успех;
- приветствие / восстановление контакта;
- движение влево и вправо.

Состояние выбирается по совокупности статуса и текста уведомления. Явные запросы ответа, ошибки и проблемы соединения имеют больший приоритет, чем обычные рабочие слова.

## Интерфейс

`0.6.0` использует одну grouped-settings дизайн-систему:

- крупная иерархия заголовков;
- мягкие карточки и системные отступы;
- короткие названия действий;
- пояснение отдельной вторичной строкой;
- видимая кнопка «назад» на вложенных экранах;
- целиком нажимаемые строки переключателей;
- контекстные переходы между связанными разделами.

Основные разделы: **Питомец**, **Реплики**, **Анимации**, **Стенд**, **Подключение**, **Поведение**, **Обновления**, **Помощь**.

Обычный пользовательский интерфейс избегает технического английского там, где он не нужен. Названия ChatGPT/GitHub и форматы APK/ZIP/PNG/WebP остаются как есть.

## Подключение к ChatGPT

`NotificationListenerService` отслеживает настроенное приложение-источник (по умолчанию `com.openai.chatgpt`).

Для устойчивости используются:

- периодическая проверка активных уведомлений;
- повторная синхронизация после изменений;
- защита от устаревших параллельных результатов;
- повторное подключение с задержкой после ошибок;
- дополнительная проверка из работающего foreground overlay.

На HONOR/MagicOS для максимальной устойчивости рекомендуется разрешить автозапуск и работу в фоне. См. [docs/magicos.md](docs/magicos.md).

## Обновления

### Из production-сборки

Стабильный `com.mr4erk.codexpet` проверяет последний GitHub Release и может:

- уведомить о новой версии;
- скачать APK заранее;
- ограничить автоматическую загрузку Wi‑Fi;
- передать проверенный APK системному Android Installer.

### Из test/debug-сборки

`com.mr4erk.codexpet.debug` тоже может проверить GitHub. Если production-приложение ещё не установлено, тестовая сборка предлагает установить стабильный `com.mr4erk.codexpet` рядом с собой. После этого production-версия обновляет уже сама себя.

Перед установкой GitHub APK проверяются:

1. стабильный GitHub Release;
2. точное имя `codex-pet-<version>.apk`;
3. HTTPS и допустимый размер;
4. SHA-256 файла выпуска;
5. package `com.mr4erk.codexpet`;
6. версия APK;
7. закреплённый production signing certificate.

Ручной APK можно выбрать через системный файловый выбор Android. В production принимается только более новая версия того же приложения с той же подписью. В debug дополнительно допускается production APK, но только с официальной production-подписью.

Android-системное подтверждение установки не обходится.

## Приватность

Тексты уведомлений и задач обрабатываются локально и не отправляются в GitHub. Сеть используется только механизмом обновления. В приложении нет analytics, Crashlytics, ads или trackers.

Подробнее: [docs/privacy.md](docs/privacy.md).

## Сборка

Требования: JDK 17, Android SDK 36.

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
./gradlew assembleRelease
```

PR gate:

1. unit tests;
2. Android lint;
3. debug APK;
4. minified release candidate;
5. проверка applicationId debug/release APK.

Verify-job сохраняет debug APK и отдельный **unsigned minified release candidate** для дополнительной проверки.

## Production release

Production CI требует четыре GitHub Actions Secrets:

- `CODEX_PET_KEYSTORE_BASE64`;
- `CODEX_PET_KEYSTORE_PASSWORD`;
- `CODEX_PET_KEY_ALIAS`;
- `CODEX_PET_KEY_PASSWORD`.

Без них неподписанный APK не публикуется как stable.

При наличии secrets workflow:

1. собирает minified release;
2. проверяет `com.mr4erk.codexpet`;
3. проверяет APK через `apksigner`;
4. сверяет SHA-256 сертификата с закреплённой production identity;
5. создаёт APK и `.sha256`;
6. публикует immutable GitHub Release `v<version>`.
