# Codex Pet 0.6.0

Первый production-кандидат после полного прохода по надёжности, интерфейсу и обновлениям.

## Баблы

- Исправлено положение бокового хвоста у коротких однострочных реплик.
- Одиночный боковой бабл теперь центрируется относительно питомца, поэтому хвост естественно указывает в его центр.
- Если безопасный диапазон хвоста схлопывается из-за малой высоты бабла и больших скруглений, хвост центрируется по телу бабла вместо смещения к краю.
- Добавлены отдельные unit-тесты короткого однострочного случая.
- Стенд 1–5 баблов использует короткую строку как обязательный первый сценарий и обновляет масштаб после возврата из настроек.

## Интерфейс

- Все основные пользовательские экраны переведены на одну grouped-settings дизайн-систему с мягкими поверхностями, крупной иерархией и компактными строками настроек.
- Вложенные экраны получили видимую кнопку «назад»; главный экран остаётся корневым.
- Строки с переключателями нажимаются целиком, а не только по маленькому тумблеру.
- Названия действий сокращены до 1–3 понятных слов; пояснения вынесены во вторичный текст.
- Убраны лишние английские служебные слова из обычного пользовательского интерфейса. Английский остаётся только для названий ChatGPT/GitHub и форматов APK/ZIP/PNG/WebP или на техническом экране диагностики.
- Старый `MainActivity` и его отдельный устаревший интерфейс удалены.
- Цвета темы и системных панелей синхронизированы с новой дизайн-системой.

## Предпросмотр

- В «Питомец» размер меняется прямо в живом предпросмотре во время движения ползунка.
- В «Реплики» масштаб сразу меняет реальный `SpeechBubbleDrawable`: ширину, шрифт, отступы, скругление и хвост рядом с текущим питомцем.
- В «Анимации» скорость видна в предпросмотре до сохранения значения.

## Навигация

- Главный экран стал компактным центром: текущее состояние → питомец → система.
- Разделы имеют короткие названия: «Питомец», «Реплики», «Анимации», «Стенд», «Подключение», «Поведение», «Обновления», «Помощь».
- Добавлены контекстные перекрёстные переходы между связанными разделами без дублирования длинных действий.

## Обновления

- Экран обновлений работает и в тестовой сборке, а не показывает заглушку.
- `com.mr4erk.codexpet.debug` может проверить GitHub и безопасно установить production `com.mr4erk.codexpet` рядом с собой.
- GitHub APK принимается только если совпадают:
  - package `com.mr4erk.codexpet`;
  - версия выпуска;
  - SHA-256 файла GitHub Release;
  - постоянный production-сертификат.
- Ручной APK в тестовой сборке также может быть production APK, но только с тем же закреплённым production-сертификатом.
- После первой production-установки стабильный Codex Pet обновляет уже сам себя.
- Названия действий упрощены: «Проверить», «Скачать», «Установить», «Разрешить», «APK-файл», «GitHub».

## Release engineering

- Версия: `0.6.0`, versionCode `8`.
- Production applicationId: `com.mr4erk.codexpet`.
- Debug applicationId: `com.mr4erk.codexpet.debug`.
- Production signing certificate SHA-256 остаётся закреплённым в CI.
- PR gate: unit tests, lint, debug APK, minified release APK, проверка applicationId обоих APK.
- Verify-job сохраняет отдельно debug APK и неподписанный minified release-кандидат для дополнительной проверки.
- Main release job принимает только полный набор production signing secrets, проверяет `apksigner`, package id и закреплённый сертификат перед публикацией GitHub Release `v0.6.0`.

## Ручная проверка перед первым production выпуском

1. Перетащить питомца с одной короткой репликой по центру, к левому и правому краю — хвост не смещается и не мерцает.
2. Проверить 1, 2, 3, 4 и 5 баблов; затем малый и большой масштаб.
3. Проверить portrait/landscape и ситуацию, когда пять баблов не помещаются — лишние переходят на следующую страницу.
4. Изменить размер питомца и масштаб реплик — предпросмотр меняется во время движения ползунка.
5. Проверить каждую анимацию и изменение её скорости.
6. Проверить все переходы «назад» и перекрёстные ссылки разделов.
7. Проверить восстановление уведомлений после перезапуска listener и после возврата в приложение.
8. В тестовой сборке открыть «Обновления», проверить GitHub и установить production APK после появления `v0.6.0`.
9. В production-сборке проверить обновление APK той же подписью через системное подтверждение Android.
