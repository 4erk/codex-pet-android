# Codex Pet 0.5.0

Stable reliability, behavior and update release.

## Notification reliability

- Added listener heartbeat based on successful `activeNotifications` snapshots.
- Replaced one-shot rebind with repeated recovery backoff up to 60 seconds.
- Three consecutive active-notification failures now trigger controlled listener unbind/rebind instead of leaving a false `connected=true` state forever.
- Added a 5-second initial bind grace fallback for OEM half-bound states where the service exists but `onListenerConnected()` never arrives.
- Foreground overlay independently checks listener health every 30 seconds, so an OEM-killed listener can recover without reopening Codex Pet.
- Added scan generation protection so an older asynchronous reconcile cannot overwrite a newer snapshot.
- Cleans stale per-notification event bookkeeping after a full snapshot.
- Home/Connection screens expose heartbeat age, scan failure count and rebind attempts.
- Notification classification no longer relies on only `codex_remote_session`: channel/shortcut/progress/ongoing/bubble/text signals are scored conservatively, with confidence/reasons visible in diagnostics.

## Bubbles

- Retains the 0.4 stable-window drag/snap implementation with no remove/add churn during motion.
- Added an interactive in-app 1–5 bubble lab using the same `SpeechBubbleDrawable` and placement algorithm as production overlay.
- Added five-bubble safe-bound/non-overlap unit coverage.
- Oversized multi-bubble stacks now adapt to available screen height: only the bubbles that fit stay on the current page and overflow rotates to the next page.
- Added contextual navigation between pet, speech, animations, bubble lab and connection troubleshooting.

## Animation behavior

- Replaced last-text-match behavior with weighted bilingual RU/EN cue heuristics.
- Structured status remains authoritative against weak generic verbs.
- User-input, connectivity and failure phrases have higher specificity than generic work/review phrases.
- Explicit retry/resume can recover a prior error signal.
- Added a single `PetAnimationStateResolver` for steady-state priority.
- Explicit `RECONNECTING` now overrides a stale coarse `ERROR` status while recovery is already in progress.
- Completed notifications no longer pin `REVIEW`; completion uses one-shot `JUMPING` then returns to the real steady state.
- Successful reconnect can trigger one-shot `WAVING`.
- Edge snap now uses `RUNNING_LEFT` / `RUNNING_RIGHT` while the pet moves.
- Catalog descriptions now document real trigger and fallback behavior for all nine states.

## UI

- Reorganized the home screen into grouped contextual settings rather than a flat grid of equally weighted destinations.
- Added disclosure-style navigation rows, soft grouped cards and clearer primary actions.
- Grouped Pet / Speech / Animations / Bubble Lab under appearance/reactions and Behavior / Updates / Help under app settings.
- Connection screen now focuses on listener health and recovery.
- Help offers direct recovery, bubble lab, animations, diagnostics and update routes.
- Added contextual cross-links between related screens instead of forcing a return to Home for every change.

## Secure GitHub self-update

- Stable builds check the public GitHub Releases latest endpoint on startup and periodically while the foreground pet is running.
- Auto-check, auto-download and unmetered-network-only preferences are available in the Updates screen.
- Only the deterministic `codex-pet-<version>.apk` asset for the stable tag is accepted; generic/debug APK assets are rejected.
- Before an APK is accepted, Codex Pet verifies HTTPS, exact GitHub release size, release-asset SHA-256 digest, package name and exact signing certificate match with the installed app.
- A failed network check does not suppress retries for six hours; only successful checks advance the persisted check timestamp.
- Downloaded APKs are tied to the release version and stale cached installers are discarded when a newer release appears.
- Installation uses Android `PackageInstaller` with required user confirmation and explicit error/session cleanup; no silent-install bypass is attempted.
- Debug builds intentionally do not self-update into stable builds.

## Release engineering

- Version: `0.5.0`, versionCode `6`.
- PR gate: unit tests, Android lint, debug APK, minified release candidate.
- `main` requires the complete persistent release-signing secret set; missing signing configuration is a hard failure.
- Signed production APK is verified with `apksigner`.
- Successful main build publishes immutable GitHub Release `v0.5.0` with `codex-pet-0.5.0.apk` and SHA-256 checksum.
- This permanent signing identity is required for the built-in updater to install future versions.

## Manual smoke matrix

Before considering a device build healthy, verify:

1. listener receives new ChatGPT/Codex notifications after normal operation;
2. forced listener restart recovers tasks;
3. listener recovers after its service is killed while the foreground overlay remains alive;
4. overlay survives hide/show and restores after process/OEM kill when the app is reopened;
5. 1, 2, 3, 4 and 5 bubble lab layouts remain in bounds at small/normal/large bubble scales;
6. oversized/landscape bubble stacks rotate overflow instead of leaving screen bounds;
7. pet drag repeatedly crosses left/right direction without flicker;
8. snap can be interrupted by a new touch;
9. completion jumps once and returns to idle/running/review as appropriate;
10. input/error/reconnect/review/run precedence matches the displayed notification state;
11. portrait/landscape positions remain valid;
12. on HONOR/MagicOS, background/app-launch permissions are documented and listener health exposes any OEM interruption;
13. stable update check sees the current GitHub release and refuses mismatched names/signatures/digests/sizes;
14. a future same-key stable APK reaches Android's confirmation installer flow.
